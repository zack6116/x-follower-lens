# 粉丝透镜 Follower Lens

> 在 X(Twitter)的信息流、关注列表和通知页里,直接看到每个账号的粉丝数,以及"别人回复的是你哪条推文"。

X 不显示别人的粉丝数;通知里有人回复你时,也不告诉你是回你的哪句话。**粉丝透镜**把这两步都省掉:粉丝数徽标贴在用户名旁边,被回复的推文贴在通知正文上方。

## 你能得到什么

| 场景 | 你的操作 | 你得到什么 |
|---|---|---|
| 判断一个陌生账号值不值得关注 | 正常刷信息流,看用户名后面的徽标 | 粉丝数 + 分级配色(灰 < 1千 < 蓝 < 1万 < 绿 < 10万 < 橙 < 100万 < 红) |
| 看清一个账号的底细 | 鼠标停在徽标上 | 精确粉丝数、关注数、粉丝/关注比、推文数、注册时间、互动率、你和对方的关系、近 7 天粉丝变化 |
| 在别人的"正在关注"列表里找新账号 | 打开对方的关注列表 | 每行都带粉丝数和质量标签;疑似互粉号、低活跃号自动变淡,鼠标移上去恢复 |
| 通知里有人回复你,看不出在回哪句 | 打开通知页 | 回复正文上方贴出被回复的那条推文;是你自己发的会标出「你说的」 |
| 想知道被回复的那条还有没有上文 | 点上下文卡里的「跳上去 ↗」 | 一路往上串成完整线索;点「查看原帖 ↗」直接打开原推 |
| 页面太挤,name 被徽标挤坏 | 不用管 | 默认"自动"模式:放得下就在名字后面,放不下自动换到下一行 |

## 通知里的回复上下文

点赞通知会带一句被赞推文的摘要,所以点赞看得懂;**回复通知只有一句"回复 @你",看不出在回你哪句话**。打开通知页,扩展会在每条回复的正文上方贴一张卡片:

```
┌ 被回复的推文  @yourname 「你说的」 · 3小时前 ──────────────┐
│ 我这边也踩过:隔夜一句「继续」,第二天它把昨天的上下文全丢了。 │
│ ↖ 这条也是回复,还有上文            查看原帖 ↗            │
└──────────────────────────────────────────────────────┘
```

- 是你自己发的会标出「你说的」,一眼分清哪句是自己的。
- 被回复的那条本身也是回复时,会提示"还有上文",可以一路点上去。
- 数据来自**你刷到过的推文**——扩展平时只读页面已经在收的数据,顺带存一份本地索引(最多 800 条,超出丢最旧的,可在设置里清除)。

**本地没有那条推文时**:卡片显示"上下文未缓存",并给一个**「加载上下文」按钮**。只有你点它,扩展才会用你页面当前的登录态向 X 请求这一条推文(只此一条,不批量、不定时、不在后台跑)。不想让它联网,在设置面板里关掉"允许联网补取",这时只显示"原帖 ↗"链接。

## 质量标签

徽标默认最多显示 3 个标签(可在设置里改),按下面的顺序优先。

| 标签 | 含义 |
|---|---|
| 互关 / 关注了你 | 你们互相关注 / 对方关注了你但你没回关 |
| 大V | 粉丝 ≥ 1 万,且粉丝/关注比 ≥ 10 |
| 疑似互粉号 | 关注 ≥ 1000,粉丝/关注比接近 1,粉丝 < 5000 |
| 新号 | 注册不到 90 天 |
| 高互动 | 互动率 ≥ 3%(点赞+转推+回复+引用 ÷ 浏览量) |
| 低活跃 | 互动率 < 0.1%,且粉丝 ≥ 5000 |
| 老号 | 注册超过 8 年 |

![账号类型一眼看懂](store/screenshot-3.png)

- 互动率是用你**刷到过的**该账号推文累计算出来的,所以刷得越多越准。浏览量合计不足 2000 时不判断互动率。
- 阈值是经验值,不是标准答案。想调的话,改 [parse.js](parse.js) 里的 `tags` 函数。
- 标签只是辅助参考,粉丝数多少不代表内容质量。

## 安装与第一次使用

目前没有上架 Chrome 应用商店,用"加载已解压的扩展程序"安装:

1. 下载本仓库(绿色 Code 按钮 → Download ZIP),解压。
2. 在 Chrome 地址栏打开 `chrome://extensions`。
3. 打开右上角的**开发者模式**。
4. 点**加载已解压的扩展程序**,选择解压后的文件夹(里面有 `manifest.json` 的那一层)。
5. 打开或刷新 x.com(`Cmd+Shift+R` / `Ctrl+Shift+R` 强制刷新)。

**第一个可验证的动作**:打开任意一条信息流,用户名后面应该出现 `[1.23万 粉丝]` 这样的徽标。装好后不需要任何其它操作,正常刷 X 就行。

如果徽标没出现,在设置面板里打开"显示调试条",页面左下角会出现"数据包 / 用户 / 已显示"三个数字:

- 用户数一直是 0:X 的数据结构变了,读不到粉丝数。
- 用户数大于 0、已显示是 0:页面结构变了,徽标没地方放。

如果之前装过旧版,在扩展页面点它的刷新按钮,并强制刷新 x.com。

## 它怎样工作

X 的网页自己会向服务器请求数据,这些响应里本来就包含用户的粉丝数、关注数和注册时间。扩展只是**读取页面已经收到的这些响应**,然后把数字显示出来。

```
X 网页 → GraphQL 响应 ─┬→ inject.js   只读复制一份,不改请求也不改响应
                       └→ parse.js    提取用户 / 推文 / 回复关系
                          → content.js 把徽标、悬停卡、回复上下文贴到页面上
```

- 不调用 X 的官方 API,不需要登录授权、不需要 API Key。
- 补取推文用的 queryId 是从 X 自己的请求里读来的,**不硬编码**——X 发版换了也能跟上。
- 只在 `x.com` 和 `twitter.com` 上运行。

## 权限 / 数据 / 隐私

**一句话:这个扩展不收集、不上传、不出售你的任何数据。**完整说明见 [PRIVACY.md](PRIVACY.md)。

| 权限 | 用途 |
|---|---|
| `storage` | 保存你的设置、粉丝数历史记录、推文索引。全部只存在 `chrome.storage.local`。 |
| 内容脚本(`x.com` / `twitter.com`) | 读取页面已经收到的数据并显示徽标。不读取任何其它网站。 |

本扩展没有声明 `host_permissions`、`tabs`、`webRequest` 等权限。

**网络请求**:默认不主动向 X 发起任何请求,只读取页面本来就在收发的数据。唯一例外是通知页那个「加载上下文」按钮:你点它,才会用你页面当前的登录态向 X 请求被回复的那一条推文。补取请求复用页面自己的会话,扩展不保存、也不外传这些凭据。不想让它联网,在设置面板里关掉"允许联网补取"。

**本地保存的三份数据**,都能在设置面板里清除:

| 键 | 内容 | 上限 |
|---|---|---|
| `fl_settings` | 你的所有开关和布局选择 | — |
| `fl_hist` | 你浏览过的账号的用户名、粉丝数、记录时间 | 3000 个账号 × 每个 40 个数据点 |
| `fl_ctx` | 你刷到过的推文 id、正文(最多 400 字)、作者、回复关系 | 800 条,超出丢最旧的 |

不读取你的密码、私信或登录凭据;不含任何统计、广告或跟踪代码;不使用远程托管的代码。

## 使用边界

- **依赖 X 网页内部的数据结构和页面元素。** X 改版后可能失效,修复通常只需要改 `parse.js`(数据字段)或 `content.js`(页面位置)。
- **只支持桌面版 Chrome**(及 Edge 等 Chromium 浏览器),`manifest.json` 要求 Chrome 111 及以上。
- **粉丝数变化只能从你第一次刷到这个账号开始记录**,不会有更早的历史。
- **只有已经载入数据的账号才有徽标**,所以向下滚动时,新出现的推文会稍晚一点才显示。
- **回复上下文依赖本地索引。** 索引里没有那条被回复的推文时,卡片显示"上下文未缓存",需要你点「加载上下文」补取;如果这个标签页还没向 X 取过单条推文,补取会先提示你去 X 里打开任意一条推文(之后这个标签页就能用了)。点「原帖 ↗」则任何时候都能打开原推。
- **右侧"推荐关注"栏地方窄**,只显示粉丝数,不显示标签。
- 标签阈值是经验值,不是标准答案;粉丝数多少不代表内容质量。
- `store/screenshot-*.png` 仍是 0.2.x 时期拍的,还没有"通知里的回复上下文"那一屏;重新上架前需要重拍。

## 项目结构

| 文件 | 作用 |
|---|---|
| [manifest.json](manifest.json) | 扩展配置 |
| [inject.js](inject.js) | 在页面里截取 X 自己发出的数据响应(只读);按需补取那一条推文 |
| [parse.js](parse.js) | 从响应里提取用户信息、回复关系,并判断质量标签 |
| [content.js](content.js) | 把徽标、悬停卡、回复上下文插到页面上,记录历史与索引 |
| [content.css](content.css) | 徽标、悬停卡、回复上下文卡片的样式 |
| [popup.html](popup.html) / [popup.js](popup.js) / [popup.css](popup.css) | 设置面板 |
| [tests/](tests) | `parse.js` 纯函数的单元测试 |
| [store/](store) | 上架材料:商店文案、截图、宣传图 |
| [PRIVACY.md](PRIVACY.md) | 隐私政策(中英) |
| [CHANGELOG.md](CHANGELOG.md) | 版本变更 |
| [icons/](icons) | 图标(`icon.svg` 是源文件) |

node --test tests/parse.test.cjs
